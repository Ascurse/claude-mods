# /bugcast

Разбирает запись экрана и выдаёт готовый баг-репорт: текст для трекера, скриншоты-доказательства и одну самодостаточную страницу, которую можно переслать кому угодно.

Смотрит и картинку, и речь: что тестировщик показывает и что проговаривает вслух.

## Обозначения

`ПАПКА` — папка этого навыка (та, где лежит этот файл). Все команды ниже запускают скрипты из `ПАПКА/scripts/`.

`PY` — команда запуска Python: `python3` на macOS и Linux, `python` на Windows (там `python3` открывает магазин приложений вместо запуска).

## Шаг 0 — настройка (один раз)

Проверь готовность:

```
PY "ПАПКА/scripts/setup.py" --json
```

Разбирай ответ по полям:

- `can_proceed: true` — всё готово, молча иди к Шагу 1. Не сообщай пользователю, что настройка в порядке.
- `missing_binaries` не пусто — нужен ffmpeg. На macOS: `brew install ffmpeg`. На Windows: `winget install Gyan.FFmpeg`, и после установки предупреди, что окно надо перезапустить, иначе программа не видна. Выполняй установку сам, спросив согласия.
- `has_api_key: false` — нужен ключ для расшифровки речи. Скажи, что ключ бесплатный и берётся на console.groq.com/keys, и спроси его через `AskUserQuestion` — так он попадёт в поле ответа, а не в переписку. Полученный ключ запиши в `~/.config/watch/.env` строкой `GROQ_API_KEY=...` (без кавычек и без комментария в конце строки), туда же допиши `WATCH_DETAIL=balanced` и `SETUP_COMPLETE=true`.

Записав ключ, сразу проверь его живым запросом — ошибка должна вылезти здесь, а не через две минуты на первом ролике:

```
PY -c "import os,urllib.request;k=[l.split('=',1)[1].strip() for l in open(os.path.expanduser('~/.config/watch/.env'),encoding='utf-8') if l.startswith('GROQ_API_KEY=')][0];r=urllib.request.Request('https://api.groq.com/openai/v1/models',headers={'Authorization':'Bearer '+k,'User-Agent':'watch-skill/1.0 (+claude-code; python-urllib)'});print(urllib.request.urlopen(r).status)"
```

Ответ `200` — ключ рабочий. Неверный ключ роняет команду с `HTTPError: 401` и телом `Invalid API Key` — скажи об этом и спроси ключ заново. Ошибка сети — скажи прямо, что сервис недоступен, и не выдумывай обходных путей.

**Заголовок `User-Agent` в команде обязателен, не убирай его.** Без него запрос идёт с подписью `Python-urllib`, и защита сайта отвечает `403 error code: 1010` независимо от ключа — рабочий ключ выглядит как сломанный. Тот же заголовок по этой же причине стоит в `scripts/whisper.py`.

## Шаг 1 — получить кадры и расшифровку

```
PY "ПАПКА/scripts/watch.py" "<путь к записи>"
```

Затем прочитай инструментом Read все кадры, которые скрипт перечислит, — они и есть твои глаза. Запомни рабочую папку из последней строки вывода: она понадобится на Шаге 4.

Запись длиннее 10 минут — скажи об этом и спроси, какой участок разбирать, вместо разреженного прохода по всему файлу (`--start 2:15 --end 2:45`).

В расшифровке ищи места, где тестировщик показывает пальцем — «вот здесь», «обрати внимание», «смотри». Картинка в такие моменты меняется мало, и отбор кадров их пропускает. Нашёл такие — повтори разбор с `--timestamps 4:32,7:10`, чтобы кадры взялись ровно на этих секундах.

## Шаг 2 — собрать текст

Один баг — один блок. В записи несколько разных багов — раздели на несколько блоков, каждый самостоятельный, с наскво́зной нумерацией.

```
## Баг 1. <Короткий заголовок: что сломано, а не что делали>

**Где:** экран/раздел; окружение и устройство, если названы вслух
**Шаги:**
1. …
2. …
**Ожидалось:** …
**Фактически:** …
**Отметки в записи:** 0:42 — момент, где видно проблему
**Серьёзность:** блокер / серьёзный / средний / мелкий — с одной строкой обоснования
**Не видно из записи:** чего не хватает, чтобы воспроизвести
```

Правила заполнения:

- **Не додумывать.** Того, что не сказано вслух и не видно на кадрах, в отчёте нет. Всё недостающее уходит в «Не видно из записи», а не в «Шаги».
- Расходятся слова и картинка — написать оба и пометить расхождение. Экран важнее сказанного.
- Шаги пишутся по действиям на экране, а не пересказом речи.
- Отметка времени ставится на каждый спорный или неочевидный пункт, чтобы проверяющий открыл запись на нужной секунде.
- Серьёзность — это предположение по увиденному, так и подписывать.
- Текст на русском, без англицизмов, понятный человеку, который запись не смотрел.

## Шаг 3 — собрать папку с доказательствами

Покажи текст в ответе и спроси согласия собрать папку. Без согласия — остановись на этом.

Папка кладётся рядом с записью и называется по её имени: `запись/`.

**Скриншоты.** Для каждого бага выбери моменты, где ошибка видна лучше всего: обычно один кадр, два-три — когда без предыстории непонятно, что произошло. Кадры из Шага 1 для этого не годятся, они шириной 512 точек. Пересними выбранные секунды из исходной записи в полном качестве:

```
ffmpeg -y -loglevel error -ss <секунда> -i "<запись>" -frames:v 1 -q:v 2 "<папка>/баг-1_00-42.jpg"
```

Имя файла связывает картинку с багом и со временем в ролике. Пересняв, открой кадры инструментом Read и убедись, что на них действительно то, что нужно: промах по времени даёт пустой экран, и это надо поймать здесь, а не отдать пользователю.

**Три файла в папке:**

1. `отчёт.md` — текст из Шага 2. Под каждым багом строка `**Скриншоты:** баг-1_00-42.jpg` — чтобы при копировании в трекер было ясно, какие файлы к какому багу перетаскивать.
2. Сами `.jpg` — вложения для трекера, в полном разрешении.
3. `баглист.html` — страница для пересылки.

**Страница.** Напиши её обычным HTML со ссылками на соседние картинки (`<img src="баг-1_00-42.jpg">`), простую и без внешних подключений: заголовок с именем записи и датой, дальше по блоку на баг — заголовок, серьёзность, шаги, ожидалось-фактически, под ними скриншоты с подписью времени. Затем вшей картинки внутрь:

```
PY "ПАПКА/scripts/inline_images.py" "<папка>/баглист.html"
```

После этого страница самодостаточна: открывается двойным щелчком на любой машине, без интернета и без соседних файлов. Скрипт печатает, сколько картинок вшил и сколько весит итог; больше десяти мегабайт — скажи пользователю, что мессенджер может не принять.

Проверь результат, а не поверь ему: в готовом файле не должно остаться ни одной ссылки вида `src="` без `data:`. Осталась — страница не самодостаточна, разбирайся, а не отдавай.

## Шаг 4 — прибрать

Рабочая папка из Шага 1 удаляется только после того, как скриншоты пересняты и папка собрана. Дальнейших вопросов по записи не ожидается — удали её; ожидаются — оставь и скажи, где лежит.

## Границы

- В трекер ничего не публикуй и никуда не отправляй — прикрепляет человек.
- Не чини баг и не лезь в код проекта.
- Не решай, дубль это или нет, — в трекере смотрит человек.
- Наружу уходит только звуковая дорожка, и только в сервис расшифровки. Видео, кадры и отчёт остаются на машине. Не предлагай способов, которые нарушают это правило.

## Если что-то сломалось

- `Unrecognized option 'vsync'` — старая копия скриптов. В этой папке ошибка исправлена; проверь, что запускается `ПАПКА/scripts/watch.py`, а не скрипт из стороннего плагина.
- Расшифровка пустая, кадры есть — не сработал ключ или в записи нет речи. Скажи об этом прямо и разбери по кадрам, пометив, что слов не было.
- Скрипты взяты из проекта `bradautomates/claude-video` под лицензией MIT (`LICENSE-watch` рядом) и доработаны: исправлена совместимость с ffmpeg 9, убрана ненужная зависимость `yt-dlp`.
