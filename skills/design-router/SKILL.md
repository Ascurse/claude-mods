# Design Router

Навыки оформления из таблицы ниже помечены `disable-model-invocation: true` — сам я их вызвать не могу,
их запускает пользователь через `/имя`. Этот навык закрывает разрыв: определить, какой из них
подходит, и предложить пользователю его запустить.

## Как пользоваться

1. Определи форму задачи по таблице ниже.
2. Назови пользователю один навык и одной строкой — почему именно он.
3. Задача не ложится однозначно — задай **один** уточняющий вопрос из колонки «что спросить».
4. Пользователь запускает навык сам: `/имя-навыка`. Не пытайся вызвать его через Skill — не сработает.

## Границы

Эти навыки я вызываю сам, роутер для них не нужен — не подменяй их таблицей выше:

- `hallmark` — разбор и правка визуального качества готовой страницы, борьба с «сгенерированным» видом
- `refactoring-ui` — иерархия, отступы, цвет, глубина в существующем интерфейсе
- `frontend-design` (плагин) — общее направление при создании нового интерфейса

А эти запускает только пользователь, но они не про эстетику — предлагай их отдельно, не через таблицу:

- `web-quality-audit` — Lighthouse: производительность, Core Web Vitals, SEO
- `web-design-guidelines` — семантика разметки, клавиатура и фокус, формы и состояния

Задача про доступность, скорость загрузки или семантику — это два последних пункта, а не таблица.
