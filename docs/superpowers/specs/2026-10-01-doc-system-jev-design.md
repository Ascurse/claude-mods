# doc-system + Jev: сортировка журнала и проверка новой записи

Дата: 2026-10-01. Статус: проект согласован в обсуждении, ждёт проверки спецификации.

## Зачем

Журналы `docs/journal/` разрастаются (`psychologist-backoffice`: `gotchas.md` — 84 записи / 124 КБ,
`decisions.md` — 59 / 92 КБ), а решение «оставить / сжать / в архив / удалить» на шаге 2b навыка
сейчас целиком на основной модели и не повторяемо. Вторая дыра — правило «разделяй носители»
(комментарий в коде или журнал) держится только на доброй воле модели при записи.

Jev (`jev ask`) — быстрая (~0,4 с, ~400 токенов на запись) модель типизированных суждений:
`choice` с вероятностями, `score`, `noul` (да/нет). Он видит только переданный текст, репозиторий
не читает — поэтому всё, что проверяется механически, считается до него.

## Решения, принятые в обсуждении

- Берём оба сценария: сортировку существующего журнала и проверку новой записи.
- **Jev только советует.** Скрипт ничего не правит. Архив и удаление — только после явного «да»
  пользователя по каждой записи (как и сейчас требуют правила).
- Устройство — один скрипт в папке навыка (вариант B). Текст-только (A) отклонён: модель каждый раз
  собирает JSON и сигналы по-разному. Хук Claude Code (C) отклонён: ломает кросс-агентность навыка.

## Компонент: `~/.agents/skills/doc-system/scripts/journal-jev.py`

Одна зависимость — стандартная библиотека Python и `git`/`jev` в `PATH`.

### Режим `triage <docs/journal>`

1. **Разбор.** Файлы `decisions.md`, `gotchas.md`, `glossary.md`; архивы (`*-archive.md`) не
   читаются. Запись — от строки `## ` до следующей `## `. Из заголовка — дата `YYYY-MM-DD`
   (если есть), из поля «Где это в коде» — пути трёх видов: в обратных кавычках, markdown-ссылки
   (относительно файла журнала), якоря `путь:символ @ SHA`.
2. **Механические сигналы:**
   - `paths_missing` — упомянутые пути, которых нет на диске;
   - `code_changed` — число коммитов по этим путям после якоря SHA (`git log SHA..HEAD -- путь`),
     а без якоря — после даты записи (`git log --since=<дата> -- путь`);
   - `oversize` — поля длиннее 4 предложений или 600 символов;
   - `chronicle` — номера бидов/веток/задач (`bd-…`, `[A-Z]+-\d+`, `feature/…`).
3. **Jev** (`jev ask`, по одному вызову на запись; `state` = текст записи + сигналы):
   - `action`: `choice` — `keep` / `compress` / `archive` / `delete`;
   - `derivable`: `noul` — факт выводится из чтения кода;
   - `hypothesis`: `noul` — причина не подтверждена.
4. **Вывод.** Таблица, сортировка от «скорее убрать» к «оставить»: файл, заголовок, сигналы,
   вердикт, уверенность. Уверенность ниже 0,6 → метка «на решение человеку». `--json` — то же
   машинно для основной модели.

### Режим `check` (черновик записи в stdin)

1. **Механика:** есть ли «Где это в коде»; `oversize`; `chronicle`; похожие записи в журнале
   (пересечение слов заголовка, без Jev).
2. **Jev:**
   - `carrier`: `choice` — `code_comment` (про одно место в коде) / `gotcha` / `decision` /
     `glossary` / `not_journal` (статус задачи, пересказ работы, выводится из кода);
   - `hypothesis`: `noul` — причина не подтверждена, а метки `[гипотеза]` нет.
3. **Вывод:** одна строка — вердикт, уверенность, замечания механики. Код выхода всегда 0:
   это совет, не запрет (лишний барьер при записи ведёт к тому, что запись не делают вовсе).

### Отказ Jev

Нет `jev` в `PATH`, нет ключа, ошибка или таймаут вызова → колонки вердикта `—/без Jev`, сигналы
выводятся, код выхода 0. Причина отказа — одной строкой в stderr, без содержимого ключа.

## Изменения в навыке (после замера)

- `SKILL.md`, шаг 2b: сначала `journal-jev.py triage`; по таблице — список предложений;
  архив/удаление — после подтверждения по каждой записи.
- `SKILL.md`, шаг 3 и `references/agents-journal-section.md`: необязательная строка «если в
  окружении есть `jev` — прогнать черновик записи через `journal-jev.py check`».
- `SKILL.md`, «Что НЕ делать»: «вердикт Jev — совет, не основание удалить запись без
  подтверждения».

Если замер Jev не прошёл — встраиваются только механические сигналы (режимы работают с флагом
`--no-jev` по умолчанию), Jev-вопросы в навык не попадают.

## Проверки

**`--selftest`** на встроенном тестовом журнале (каждая проверка должна уметь упасть):
- разбор заголовков и дат, включая запись без даты;
- извлечение путей всех трёх видов; запись без путей; запись с несуществующим путём →
  `paths_missing` непуст;
- `chronicle` ловит `bd-abc` и `TECH-123`, не ловит обычный текст;
- без `jev` в `PATH` — сигналы есть, код выхода 0, вердикт `без Jev`.

**Замер пользы Jev** (решает, встраивается ли Jev):
- `triage`: 20 записей `psychologist-backoffice/docs/journal/gotchas.md` (10 старых, 10 новых),
  ручная разметка действия — делает основная модель (не Jev), пользователь проверяет выборочно.
  Прошёл, если: по «оставить / убрать» (`keep`+`compress` против `archive`+`delete`) совпадение
  ≥ 16 из 20 **и** ни одна запись с разметкой «оставить» не получила `delete` с уверенностью > 0,6.
- `check`: 10 придуманных черновиков, по 1–2 на каждый вид `carrier`; прошёл, если ≥ 8 из 10.
- Результаты (таблица совпадений) — в описание задачи в трекере, в репозиторий не коммитятся.

## Вне рамок

- Хук Claude Code на правку журнала.
- `jev rerank` для чтения журнала (пригодится, когда поиск по пути начнёт выдавать десятки записей).
- Автоматическая простановка якорей `@ SHA`.
- Правка самих журналов проектов — отдельная задача после замера.
